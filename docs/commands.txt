ШПАРГАЛКА: ЗАПУСК И РАБОТА С DOCKER COMPOSE
============================================

Все команды запускаются из корня проекта (там, где лежит docker-compose.infra.yaml).
Нужны: Go, Docker Desktop (или Docker Engine + Compose plugin), make.


1. ПЕРВЫЙ ЗАПУСК
----------------

cp .env.example .env            # настройки для локального запуска
make infra-up                   # поднять Postgres и Redis, дождаться healthy
make run                        # запустить API на http://localhost:8080
tail -f app.log                 # смотреть логи приложения (APP_ENV=local пишет в файл)

Остановить API: Ctrl+C в терминале с make run.


2. MAKE-КОМАНДЫ
---------------

make infra-up                   # поднять Postgres и Redis
make infra-down                 # остановить; данные базы сохраняются
make infra-reset                # удалить всё вместе с данными и поднять заново (миграции применятся с нуля)
make run                        # запустить API


3. ТО ЖЕ САМОЕ БЕЗ MAKE
-----------------------

docker compose -f docker-compose.infra.yaml up -d --wait     # поднять в фоне и дождаться healthy
docker compose -f docker-compose.infra.yaml down             # остановить
docker compose -f docker-compose.infra.yaml down -v          # остановить и удалить данные (volume)
go run ./cmd/api                                             # запустить API


4. СОСТОЯНИЕ И ЛОГИ КОНТЕЙНЕРОВ
-------------------------------

docker compose -f docker-compose.infra.yaml ps               # список контейнеров и статус (healthy / unhealthy)
docker compose -f docker-compose.infra.yaml logs -f          # логи всех контейнеров в реальном времени
docker compose -f docker-compose.infra.yaml logs -f postgres # логи только Postgres
docker logs --tail 50 demo-postgres                          # последние 50 строк лога контейнера
docker inspect --format '{{.State.Health.Status}}' demo-postgres   # статус healthcheck


5. POSTGRES
-----------

docker exec -it demo-postgres psql -U demo -d demo-db        # открыть консоль psql

Внутри psql:
  \dt                           -- список таблиц
  \d users                      -- структура таблицы
  SELECT * FROM roles;          -- роли
  SELECT id, email, name, role_id, created_at FROM users;
  \q                            -- выйти

Одной командой, без входа в консоль:
docker exec demo-postgres psql -U demo -d demo-db -c "SELECT * FROM users;"

Подключение из IDE (DataGrip, DBeaver, GoLand):
  host=localhost port=5432 user=demo password=demo database=demo-db


6. REDIS
--------

docker exec -it demo-redis redis-cli    # открыть консоль redis-cli

Внутри redis-cli:
  KEYS session:*                # все действующие сессии (KEYS — только для локальной отладки)
  GET session:<jti>             # id пользователя, которому принадлежит сессия
  TTL session:<jti>             # сколько секунд сессии осталось жить
  DEL session:<jti>             # отозвать сессию вручную: оба токена пары сразу перестанут работать

  jti — поле внутри токена (JWT), у access и refresh одной пары оно одинаковое.
  Посмотреть содержимое токена: вставить его на https://jwt.io
  (только локальные токены: боевые на сторонние сайты не вставляем)
  FLUSHALL                      # удалить всё: все пользователи разлогинятся
  exit


7. ПРОВЕРКА API
---------------

# Регистрация (role: user; admin и другие служебные роли при регистрации запрещены)
curl -i -X POST localhost:8080/api/v1/auth/register \
  -d '{"email":"ivan@mail.com","password":"secret123","name":"Иван","role":"user"}'

# Вход: в ответе access_token и refresh_token
curl -i -X POST localhost:8080/api/v1/auth/login \
  -d '{"email":"ivan@mail.com","password":"secret123"}'

# Текущий пользователь (нужен access_token)
curl -i localhost:8080/api/v1/users/me -H "Authorization: Bearer <access_token>"

# Создать пост (нужен access_token)
curl -i -X POST localhost:8080/api/v1/posts -H "Authorization: Bearer <access_token>" \
  -d '{"title":"Мой первый пост","content":"Привет, мир!"}'

# Новая пара токенов (старые access_token и refresh_token после этого не работают)
curl -i -X POST localhost:8080/api/v1/auth/refresh -d '{"refresh_token":"<refresh_token>"}'

# Выход (access_token и refresh_token сразу перестают работать)
curl -i -X POST localhost:8080/api/v1/auth/logout -d '{"refresh_token":"<refresh_token>"}'


8. ЧАСТЫЕ ПРОБЛЕМЫ
------------------

"port is already allocated" при make infra-up
  Порт 5432 или 6379 занят (например, локальным Postgres). Найти, кто занял:
  lsof -i :5432
  Остановить его или поменять порт в docker-compose.infra.yaml и POSTGRES_PORT в .env.

"connection refused" при make run
  Инфраструктура не поднята или ещё не готова: make infra-up, затем
  docker compose -f docker-compose.infra.yaml ps — оба контейнера должны быть healthy.

Изменил migrations/001.sql, а в базе ничего не поменялось
  Миграции выполняются только при первом создании базы: make infra-reset (данные удалятся).

"relation "users" does not exist"
  База создана до появления миграций: make infra-reset.

Не видно логов приложения в консоли
  При APP_ENV=local логи пишутся в файл: tail -f app.log
